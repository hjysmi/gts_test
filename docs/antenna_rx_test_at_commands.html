Antenna RX Test 场景 AT 命令速查手册

针对 4G/NR 各测试场景 CheckBox 勾选对应 Modem 指令深度解析

一、 页面统一设定基准

在 Antenna RX Test 页面设定如下：

  • 第一行选择 (Force RX): True （对应强迫接收开启，即 intForceRx = 1）
  • 第二行选择 (SCC Follow PCC): False （对应辅小区跟随关闭，即 intCssFollowPcc = 0）
  • SIM 卡槽 (仅限 NR 5G 生效): SIM1 （对应 sim = 0）
底层逻辑公式：
4G 命令格式：AT+EGMC=1,"rx_path",intForceRx,intCssFollowPcc,pCell2Rx,pCell4Rx,sCell2Rx,sCell4Rx
NR 命令格式：AT+EGMC=1,"nr_rx_path",intForceRx,intCssFollowPcc,pCell2Rx,pCell4Rx,sCell2Rx,sCell4Rx,sim

二、 天线掩码二进制转换原理

每组复选框（CheckBox）的勾选状态会在后台通过二进制按位或（OR）操作折算成 10 进制整型传递给指令：

复选框名称 对应二进制位 选中时的权值 (Dec) PCell / SCell 2RX (2个框) PCell / SCell 4RX (4个框)
rx1 1 << 0 1 ✅ 支持勾选 ✅ 支持勾选
rx2 1 << 1 2 ✅ 支持勾选 ✅ 支持勾选
rx3 1 << 2 4 ❌ 不存在 ✅ 支持勾选
rx4 1 << 3 8 ❌ 不存在 ✅ 支持勾选

三、 场景对应命令速查表

场景 1：测 Combine (全勾选)

勾选配置：所有 2RX (rx1+rx2)、4RX (rx1+rx2+rx3+rx4) 全选。
计算出的掩码值：pCell2Rx = 3, pCell4Rx = 15, sCell2Rx = 3, sCell4Rx = 15

Antenna Test (4G) 点击 Write 依次发送：

1. 初始化（全开）：AT+EGMC=1,"rx_path",1,0,3,15,3,15 2. 设置值（全开）：AT+EGMC=1,"rx_path",1,0,3,15,3,15

Antenna Test (NR) 点击 Write 发送：

AT+EGMC=1,"nr_rx_path",1,0,3,15,3,15,0
💡 特别说明：在 Combine 下，由于用户选择的掩码状态和 4G 复位初始化的状态刚好一致（都是全通路开启），所以 4G 第一步与第二步发送的命令在字面上完全一致。

Antenna Test (NR) 点击 Write 发送：

四、 4G (LTE) 双步执行原理解析

在 4G 设定下，如果直接将天线切到单通路（如只保留 rx1），由于物理通路的骤变极易引发信号失锁与网络异常。为此，MediaTek 的底层架构设计采用了两步复位法：

  1. 第一步 initEgmcAnt4G()：全通路复位复原
    当点击 Write 时，代码无条件率先向 Modem 投递复位包：
    AT+EGMC=1,"rx_path",1,0,3,15,3,15
    这使得 Modem 底层硬件重新连通所有的接收射频电路，将网络信号和指标重置回最大化全开状态。
  2. 第二步 setEgmcAntForUser()：应用自定义值
    在全通路复位操作收到 Modem 成功的回执 (OK/Success) 后，UI Handler 捕获到 MSG_INIT_ANTENNA_EGMC_4G，才进一步拼装出用户勾选的具体通道状态，将其下发。

因此，在测试类似 Rx0、Rx1 等单路或偏向设置时，两步机制的切换能有力保证硬件状态的安全过度，而在测试 Combine（全开） 状态时，则会出现连续发送两次相同命令的特殊表现。
